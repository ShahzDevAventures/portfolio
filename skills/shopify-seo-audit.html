The problem

SEO audits list everything a crawler can flag and rank none of it. The merchant fixes the easy rows, and the duplicate Product JSON-LD or the blocked sitemap stays exactly where it was.

The script checks the mechanical things. The skill decides what matters.

A crawler samples the sitemap by page type and records the same checks every time. Claude then confirms each finding on the live page, reads the page types a person would, and ranks the result.

  1. Crawl. The script reads robots.txt and the sitemap, samples five URLs per page type, and checks titles, meta descriptions, H1s, canonicals, noindex, Product JSON-LD, collection-path product links, alt text and thin pages.
  2. Confirm. Every script finding is checked on the real page before it goes in the report, because a crawl without JavaScript misses tags that apps inject.
  3. Review by page type. The homepage, the top three collections and the top three products get the on-page checklist.
  4. Map keywords. With a Search Console export, it builds a baseline, maps intent to page types, and sorts queries in positions 11 to 20 into optimise, maxed out or ignore.
  5. Rank. Anything blocking indexing comes first, then duplicate signals, then metadata on high-traffic pages, then gaps in the keyword map.

One report the merchant and the developer can both work from.

A single HTML file styled like the Shopify admin. It opens with three sentences: the biggest blocker, the biggest opportunity, and what to do this week.

  • Fix now: each finding with its evidence, who fixes it, and the effort
  • Keyword map: one target page per keyword, existing or new
  • Searches on page 2 of Google: every query in positions 11 to 20, marked optimise, maxed out or ignore
  • Findings by page type for the homepage, collections, product pages and blog
  • Reports to request: the Search Console exports still missing

Tradeoffs

A script for the checks, judgement for the ranking.

Chose

A standard-library crawler that runs the same 17 checks every time

vs
Over

An AI reading pages and deciding what looks wrong

Gave up

Speed and Core Web Vitals, which it takes from PageSpeed Insights and Search Console field data instead

Got

Two runs on the same store produce the same findings.

Never touch a handle that already ranks.

Chose

Keep ranking URLs; when one must move, a 301 plus updated internal links

vs
Over

Tidier URL structures

Gave up

Cleaner URLs on older stores

Got

No ranking lost to a rename.

Install it

It runs best in Claude Code. In the Claude app it needs code execution with network access, because the crawler has to reach the store; without it, the skill runs a reduced audit and marks what it could not check.

Claude app

  1. Download the skill file below.
  2. In Claude, open Settings → Capabilities and turn on Code execution and file creation.
  3. Open Customize → Skills, click +, then Create skill → Upload a skill, and choose the file.
  4. Start a new chat.
Download shopify-seo-audit.zip

Claude Code

Run this once in a terminal:

npx skills add ShahzDevAventures/shopify-seo-audit

Then start Claude Code in any folder and ask for the audit.

Then say: Run an SEO audit for example-store.com
