01Evidence trail

The scope changed on day one, and the date did not.

The August statement of work described one site with the THC range behind an age gate. The client's September launch plan replaced it: gigli.com would become a brand-new, functional-only Shopify store so it could run ads, and the THC business would move to a second domain behind a 21+ gate. Design review and development started the same day; QA-ready was four days out and go-live fifteen.

The inherited theme was a Prestige base with forty agency-added sections and a 387 KB jQuery bundle shipped without source, so two full JS and CSS stacks loaded on every page. The Figma file failed its readiness audit: token binding on 0–37% of frames, text styles on 0–96%, default layer names on roughly half. Product photography did not exist yet. The client said it plainly: some bugs at go-live are part of the deal.

02Problem statement
A two-developer agency cannot hand-build a 29-section theme to a pixel spec in fifteen days, and a single large AI generation cannot be trusted to match a design file that is itself inconsistent. The build needed to be fast and checkable at the same time.
03Tradeoffs

Build as drawn, fix the design file later.

Chose

Waive the Figma readiness gate and transcribe literal values where tokens were unbound

vs
Over

Sending the file back to the designer for token binding first

Gave up

Clean token references in about a third of the CSS, replaced by literal px and hex values the specs already carried.

Got

The date. The designer fix-list went into figma_audit.json for the next design round instead of blocking this one.

Many small agents with gates, not one big generation.

Chose

Per-section research specs, then builder → verifier → fixer loops behind five release gates

vs
Over

Generating the theme in one pass and reviewing it by eye

Gave up

Tokens and wall-clock: 65M tokens and an overnight run, with 64 failing loops along the way.

Got

Every failure caught by a check, not a client. The page-integration gate alone found 16 issues no section-level test could see: header overlay, three overflow breakpoints, seams between pull-up sections.

Verified mode on a static harness before the store existed.

Chose

A local render harness with the real brand fonts, a measurement script and visual diff

vs
Over

Waiting for the new store and building against live previews

Gave up

A final pass on real data, which had to happen later with the developer.

Got

Measured parity to the Figma frames on day one, and a store that could be created in parallel.

04How we arrived at the solution

Intake, 322 decisions, then an overnight run with human check-ins at the gates.

The pipeline started with a review of four inputs: the brand book and design system, the July theme export, the prior performance sprint, and the repo history. Each of the 29 sections got a research pass that produced a brief and a spec file of computed-style assertions, and the plan surfaced 322 open questions. I answered them in one sitting: 308 by default, 13 changed, one asked back.

With the plan approved, the build ran in six waves. Builders wrote sections against the specs, verifiers measured them on the harness, fixers took the failures, up to five loops a section. At 02:10 a platform usage limit killed fourteen agents mid-task; at 02:52 all fourteen resumed from their saved transcripts with nothing lost on disk. Templates were assembled at 05:15, the page-integration gate failed with 16 items, and by 07:30 all five gates (reachability, coverage, editability, functional, performance) had passed, with a 456-item deferral ledger and a handoff document for the developer.

From there the work was human: the developer and I polished through client reviews, split the new store from the THC store, migrated catalogue and redirects, and dealt with the parts no pipeline sees, from mega-menu bands bleeding across columns to a quiz page that only broke on wide screens.

05What happened

The store launched, and the pipeline became the product.

gigli.com is live as a functional-only store with the full flavour range, build-a-box and quiz flows, and the THC business on its own domain. The same pipeline has since been pointed at the next client, and the pieces that generalise are published as installable skills.
